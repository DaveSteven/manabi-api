# JLPT 数据模型与清洗规则

## 模型

exams 保存试卷，occurrences 保存题目在某等级、试卷、大题和位置中的出现记录，questions 保存不可变内容修订，options 保存选项与答案。来源题目 ID 可以在多个出现记录中重复，不用作出现记录唯一键。

materials 保存文章、译文、字幕和资源引用，相同内容按摘要复用。occurrences.group_key 按等级、试卷、大题及父材料 ID 分组，阅读和关联听力一起出题，无父材料的题目自成一组。

question_types 提供语义化题型。assets 保存安全的相对路径、类型、大小和 MIME 类型，API 不暴露宿主机路径。

import_runs 和 quality_issues 保存导入报告；occurrence.source 保存完整来源记录和摘要，exam.source_metadata 保存试卷元数据，均不进入 App 出题响应。

用户数据使用 users、tokens、practices、practice_items、wrong_questions。token 只存 SHA-256 摘要，密码使用随机盐的 PBKDF2-SHA256。作答按用户加 PostgreSQL 行锁，避免并发重复计数。

## 清洗

1. 读取 N2/N3 normalized JSON，保存来源摘要和完整记录。
2. 出现记录 ID 包含等级、来源试卷、大题、来源题目 ID 及同一大题内该 ID 的重复序号。普通排序调整和插题不会让旧错题记录指向别的题；重复来源 ID 也不会覆盖试卷归属。
3. 题目修订摘要包含来源 ID、题干、选项、答案、解析和材料，内容变化产生新修订。
4. 来源 data_type、identity、更新时间等归入 source，App 使用简化后的领域字段。
5. 保留必要富文本，去除来源 class、事件处理器、脚本、样式。发现未转换的内嵌图片时隔离题目，不静默丢失图片。
6. 字幕时间转换为毫秒区间，无效区间记警告，原文仍可追溯。
7. 校验选项、答案、题型一致性及媒体存在性和路径边界。
8. 对比旧数据库的题干、文章、解析、译文、字幕、选项和答案，差异进入 review。
9. 同组任一题 review 则整组不发布，组内题型不一致也不发布。
10. 单事务写入，异常回滚。源文件缺失或孤立题目直接中止导入。

N3 来源编码 13 和 14 均显式映射为 context_vocabulary。44 条编码不同、语义相同的记录保留 type_alias 警告；其余题型冲突不以大题编码静默覆盖。

## 发布状态

- ready：可组题。
- review：待内容或元数据核对。
- hidden：来源试卷未发布。
- retired：不再出现在完整来源数据中，保留历史引用。

缺少解析不阻止练习；答案不合法、听力音频缺失等错误会阻止练习。结构校验通过不代表逐题人工校验了日语内容。

## 后续修订

目前不提供对外内容修改接口。核对后应记录证据，修改受控 normalized 数据再导入；旧数据库差异还需同步处理比较基线，并另存旧快照。不要直接把运行库中的 review 改成 ready 绕过校验。

原始 JSON 和媒体仍在原采集目录。新服务及导入脚本不修改原目录或旧数据库。
